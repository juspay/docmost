Mindspace into Docmost: implementation plan

How the features of mindspace are added to this docmost fork so that mindspace can be retired: what exists today, what is added, where each file goes, and the tasks in order.

Date 2026-11-25 Spec docs/superpowers/specs/2026-11-25-mindspace-into-docmost-design.md Target juspay/docmost at c956adaa Source sinha-sahil/mindspace at 149db12
For agentic workers. Required sub-skill: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Work task by task. Each task is one pull request with one commit. Read the spec together with this plan. Tick boxes are saved in your browser only; the record of progress is the merged pull requests.

Summary

Goal
Docmost gains live whiteboards, to-do boards, spreadsheets, split view, passkey sign-in as an option beside passwords, personal access tokens, an MCP endpoint, and public links that can expire. Mindspace data is then migrated and mindspace is switched off.
Architecture
Whiteboards, to-do boards and spreadsheets are live blocks: blocks inside a normal docmost page whose content lives in its own small synced document (one row in a new live_blocks table), served by the existing sync server under the name block.<blockId>. Access to a block is access to its page. Everything else is a new open-source module beside the existing ones.
Stack
What docmost already uses: React 19, Mantine 9, TipTap 3, Yjs with Hocuspocus 4.9, NestJS 11 on Fastify, Kysely on PostgreSQL, Redis, pnpm with nx, jest on the server, vitest on the client. New dependencies: @simplewebauthn/server and @simplewebauthn/browser (passkeys). Nothing else; the migration tool reads mindspace with the postgres driver docmost already has.
Reused code
Mindspace's to-do board logic and spreadsheet engine are copied in with their tests. Sachin confirmed on 2026-11-25 that permission exists. Mindspace's Svelte screens are rewritten in React.
Size
9 parts (0 to 8), 36 tasks, each one pull request. Part 3 (spreadsheet) is the largest, with 8.
Review
This plan was attacked by three independent reviewers before it was committed. Four blockers and about thirty major problems were found and fixed. See the review log.

Deviations from the spec

Where this plan differs from the spec, the plan is right and the reason is here. Most came out of the adversarial review.

Spec saysPlan doesWhy
8.1: the block node holds kind.The kind is the node type (whiteboard, todoBoard, sheet).One source of truth; a node cannot disagree with itself.
8.1: a pasted block "gets a new id and a cloned copy".Same result, but the copy is requested by the paste itself, in one call made as the person pasting. No copy request is ever stored in the page.A stored request would be carried out later by whoever opened the page next, with their access.
8.4: inserting or deleting rows and columns "is applied as one whole-sheet change".Rows and columns have stable ids. An insert or delete changes only the list of ids. Formulas are stored anchored to those ids.Rewriting shifted cells loses values and corrupts formulas when two people edit at once.
8.5: the pane is the same page with ?pane=1.The pane is recognised by an attribute on its iframe element, not by a URL parameter.The parameter is lost when a link is followed inside the pane.
8.7: scopes read and read+write.Stored as read and write; write includes read.Wording only.
8.6: nothing about cloud, recent sign-in, or two-factor.Passkeys are off on cloud; adding a passkey needs the password again; passkey sign-in is refused where two-factor is enforced.One site identity per installation; a stolen session must not become a permanent key; an enforced second factor must not be bypassed.

KindShared typesMerge rule
whiteboardelements: Y.Map, element id → whole Excalidraw element (plain object). files: Y.Map, Excalidraw file id → {attachmentId, mimeType}.Per element, the whole element. A client writes its element only if it beats the stored one (higher version, then higher versionNonce). If a remote write lands that loses to the client's own copy, the client writes its copy again. Deleted elements stay as isDeleted tombstones. Draw order is the element's index field. "Newer" means more edits, not later in time: a long offline edit of one element beats a short online one.
todometa: Y.Map (sort, hideDone). columns: Y.Map, card id → Y.Map of fields plus order and deleted. nodes: Y.Map, item id → Y.Map of fields plus columnId, parentId (null at the card's root), order and deleted.Per field. Sibling order is a fractional key (fractional-indexing-jittered, already a dependency). Nothing is removed from the maps: a delete marks the item and each of its descendants deleted. Reading never fails and never drops a live item: a live item under a deleted or missing parent goes to its card's root; a deleted card that still has a live item is shown; a parent chain that loops is cut by attaching the item with the smallest id in the loop to its card's root.
sheetorder: Y.Array of tab ids. sheets: Y.Map, tab id → Y.Map with name, frozenRows, frozenCols, rows (Y.Array of row ids), cols (Y.Array of column ids), cells (Y.Map, "rowId:colId" → cell), colWidths and rowHeights (keyed by id), merges (Y.Map, merge id → four corner ids).Per cell, last writer wins. Rows and columns have stable ids. Inserting or deleting a row or column changes only the rows or cols array, so two inserts both happen and no cell is rewritten. A formula is stored with its references anchored to row and column ids and is turned back into A1 text when read, so it follows its cells through inserts and shows #REF! when its target is deleted. The active tab is local to each person.

Global constraints

Every task includes these. A task that cannot meet one stops and reports.

  • Never open the Enterprise folders: apps/client/src/ee, apps/server/src/ee, packages/ee, packages/base-formula. Do not import from them in new code, do not read them for reference, do not copy from them. Existing imports of them in upstream files stay as they are.
  • New features do not go through the licence gate. Do not call hasFeature, useFeature or the Feature constants for anything in this plan.
  • Do not use the api_keys table, the api_key JWT type, or the route path mcp. They belong to the Enterprise feature.
  • Ported mindspace files start with a comment: // Ported from sinha-sahil/mindspace @149db12: <original path>. Port the logic unchanged unless a step says otherwise, and port its tests with it.
  • Use what docmost uses. Mantine components and CSS modules, Tabler icons, react-i18next with every user-facing string through t(), TanStack Query for server state, jotai for shared client state, Kysely for SQL, class-validator DTOs, POST for every REST endpoint. Pin new dependency versions exactly, as the manifests do.
  • Tests: server specs are *.spec.ts beside the source (jest); client and package tests are *.test.ts(x) beside the source (vitest). Write the failing test first. A test that only checks a mock was called does not count as covering a behaviour.
  • Throttling is opt-in. There is no global guard. A new controller gets a limit only by copying the pattern at core/auth/auth.controller.ts:41-42: @SkipThrottle({ ...ALL_NAMED_THROTTLERS_SKIPPED, [NAME]: false }) and @UseGuards(ThrottlerGuard). Using ThrottlerGuard without the skip map applies every named limit at once.
  • Never trust a block id. Every server path that takes one resolves it to its page and authorises on the page, in the same request, as the caller.
  • Git: branch <type>/<description> created with workforge, conventional commit message, one commit per pull request, no co-author trailer, pull request to juspay/docmost main. Never push to main. Never merge without Sachin's approval. Stack a pull request on its parent when it depends on one that is not merged.
  • Before opening a pull request: pnpm build passes, the tests named in the task pass, the full server and client suites show no failure beyond the Part 0 baseline, pnpm smoke (task 0.1) passes, and anything with a screen has been checked in a real browser with the result stated in the pull request.

The identity rule

LiveBlockIdentity is a ProseMirror plugin with appendTransaction. It ignores remote transactions, using isChangeOrigin(tr) from @tiptap/extension-collaboration as extensions.ts:222 does. After a local transaction that changed the document it walks the new document in order. The first node with a given blockId keeps it. For each later node with the same id:

  • If that id occurred fewer times in the document before this transaction (so this person's paste, alt-drag or template insert just created the duplicate): give it newId() and record origin.copies.set(newId, oldId).
  • If the duplicate was already there before this transaction (it came from merging two people's changes): give it newId() and add it to origin.created. It becomes an empty block; the first occurrence keeps the content.

The plugin also records, through transformPasted, the id of every live block in a slice this person pastes: origin.copies.set(id, id) marks it as "pasted here by me". 1.8 uses that when the server says the id belongs to another page.

The editable flow
  1. Nothing is sent until the block is about to go live (in view, or opened). A page with fifty blocks does not make fifty calls on load.
  2. If origin.copies has this blockId with a different source id: call clone { sourceBlockId, blockId, pageId }, then delete the entry. 404 → status no-access ("You do not have access to the original"), with "Replace with an empty block".
  3. Otherwise call ensure { blockId, pageId, kind }.
  4. On 409 BLOCK_ID_TAKEN:
    • the id is in origin.created (this person just inserted it and someone else took the id first): set a new uuid7(), add it to origin.created, ensure again. Nothing is lost; the block was never stored.
    • the id is in origin.copies mapped to itself (this person pasted it here from another page): set a new uuid7(), record copies.set(newId, oldId), go to step 2.
    • otherwise (the node was already in the page when this person opened it): status foreign, "This block belongs to another page", with "Replace with an empty block" for editors. Never clone in this case. This person did not ask for a copy; whoever put the node there may not be allowed to read the source.
  5. On 409 KIND_MISMATCH or 403: status error or no-access.

Rules
  • Layout is in Yjs layout. Row, column, tab and merge ids are short random strings made where the row, column, tab or merge is created.
  • An insert adds ids to the rows or cols array at a position. A delete removes ids from it. Neither touches a cell or a formula. Cells of a deleted row stay in the map and are simply never read; that is what lets an undo of the delete bring the row back with its contents.
  • Growing (writing past the end) appends ids. Two people growing at once append twice; the extra blank rows at the end are harmless. An array is capped at the limits: an insert or a grow that would pass them throws.
  • If the same id appears twice in an array (two people undid the same delete), the first occurrence counts and later ones are ignored on read.
  • A reference to a position past the current end grows the tab so the position has an id, then anchors to it.
  • If the ported engine accepts whole-row or whole-column references, anchor them by row id or column id alone.
  • A tab rename changes only name. Cross-tab references are anchored by tab id, so nothing else is written.
  • The ported functions change their argument in place and return nothing (setCellRaw, updateCellFormat, mergeCells, fillRange…). A non-structural change is always: const next = structuredClone(current); mutate(next); writeSheetChange(doc, current, next), with current read from the document in the same synchronous call. Never diff a value against itself. The ported insertRows and friends in ops.ts are not used on shared documents; they remain for seedSheet callers and the ported tests.

  • Challenges live in Redis for 300 seconds under passkey:reg:<challengeId> (value: the challenge and the user id) and passkey:login:<challengeId>, with a random challengeId in both cases, so two tabs do not overwrite each other. A challenge is read with GETDEL, so it works once.

Part 8 · Public links that expire

Decided by Sachin on 2026-11-25 (this answers Q6): a public link can have an expiry. After that date it stops working for people who are not signed in. A page can be reachable through its own share or through an ancestor's share that includes sub-pages. Today getShareForPage returns the nearest one (share.service.ts:173-231, limit(1)). Where the check goes

Inside the share service, not route by route, so that a future anonymous route inherits it and no content or attachment token is produced before the check:

Every existing refusal wins over the new one.   • Files. Images and files on a shared page are fetched with a signed token that lives one hour (token.service.ts:84) and are cached publicly for another hour (attachment.controller.ts:733). A file link copied out of the page before expiry therefore stops working at the expiry time. Shares without an expiry are unchanged.
  • Signed-in members are not served through the share. The expired response carries a slug id; the client sends a signed-in person to /p/<slug>, where docmost's normal access rules apply. The server needs no optional sign-in on public routes.

Known limits of the first release

Each is deliberate. None blocks retiring mindspace.

  • No version history inside a block. Restoring an old version of a page keeps its blocks as they are now. A block deleted since then comes back, because its row was kept.
  • Block content is not searchable. Page titles are.
  • Editing a block does not change the page's "last updated" time and sends no page-watcher notification. One exception: the first time a whiteboard gets a preview image, the page changes once.
  • Deleting a block from a page keeps its row. That is what makes undo work. There is no clean-up job; rows go when the page is permanently deleted.
  • Readers and public shares see a snapshot, not the live block. It is refreshed every 30 seconds while on screen and can be up to about a minute behind an editor. A block inserted seconds ago can show "not ready yet" to readers until the page itself is saved.
  • Functions that change by themselves (NOW, TODAY, RAND, RANDBETWEEN) show, in read-only views, exports and MCP, the value from when the snapshot was last built on the server, in the server's time zone.
  • Whiteboard merging is per element and counts edits, not time. If two people change the same shape at once, one whole change wins. A long offline edit of a shape beats a short online one and can bring back a shape someone else deleted.
  • A whiteboard that nobody has opened in a browser has no preview image (boards made by MCP or by migration). Signed-in readers see it drawn from the snapshot. On a public share its images show as placeholders until an editor opens the board once. Exports show its title and a link.
  • Whiteboard tombstones are never pruned. A board that has had very many elements deleted keeps growing slowly.
  • Sorting a sheet range and filling rewrite cell contents. A value typed into that range by someone else at the same moment can end up in a different row of the range. Inserting and deleting rows and columns does not have this problem.
  • Large sheets are capped where they would hurt. A snapshot stores display values for the first 50,000 filled cells; an exported sheet shows the first 200 rows and 50 columns with a line saying how much more there is.
  • A live block cannot be inserted inside a synced block. Where one is seen through a synced reference on another page, it shows "Open the source page to view this block".
  • Live blocks do not work in templates. The slash entries are hidden there.
  • Replacing a page from markdown (update_page_markdown) keeps live blocks by moving them to the end of the page, and refuses pages holding content that markdown cannot carry unless told to go ahead.
  • Search engines keep what they copied before a link expired. The expired page tells them not to index it, but old copies go only when they recrawl.
  • An expired link stops serving anonymous visitors only. It is not deleted: the page's editor can renew it, and signed-in members are sent to the page itself. A link with no expiry set behaves as it does today.
  • Split view loads the app twice. It is hidden below 1,024 px.
  • Passkeys assume one domain per installation, are off on cloud, and are refused where two-factor sign-in is enforced.
  • Tokens open the MCP endpoint only, not the REST API. A request body is limited to 1 MiB, so a whiteboard scene with large inline images is refused.
  • With COLLAB_DISABLE_REDIS=true and the sync server in a separate process, the API cannot reach open documents: MCP writes to blocks and pages answer 503, and a copy of a block can miss the last seconds of edits.

Major problems fixed

  • Saving. A snapshot that could not be built would have stopped the block's document from ever being saved. Now the document is saved first and a snapshot failure is recorded, not fatal (1.4). The engine gets guard tests so one cell cannot crash or stall the server (3.1).
  • Stale copies. Duplicating a page or copying a block read the stored data, which can be 45 seconds old or empty. Copies now flush the open document first (1.5, 1.6).
  • Images in copies. A duplicated whiteboard pointed at the original page's image files and broke when the original was deleted. Copies now get their own attachments (1.5).
  • Page duplication order. The draft put block copying inside a transaction that starts after the page content is already built. It is now two steps at the right places (1.6).
  • Where a block learns its page. The draft read it from editor storage, which is set late and does not update. A React context now supplies page, share and history modes, and templates are excluded (1.8).
  • API facts. This Excalidraw build has no exportToSvg; uploadFile takes an object, not a string; the retry-on-failed-save is an explicit re-queue, not a rethrow; there is no "event was handled" signal unless the handler returns one. All corrected (1.4, 1.9).
  • Package wiring. The client needs a test alias, not a tsconfig path; editor-ext must declare the dependency; the server needs a paths entry (1.1).
  • Migration order. Fixed timestamps on parallel branches would have broken start-up. Unordered migrations are allowed and files are named at rebase time (1.2).
  • Throttling. There is no default limit in docmost, so the MCP endpoint would have had none. It now has an address limit, a per-token limit and a batch cap; passkeys get their own limit (5.1, 6.2).
  • Passkeys. A stolen session could add a permanent key: adding one now needs the password, mails the owner, and admins can remove a member's keys. Sign-in now updates last login, and is refused where a second factor is enforced. The counter check is left to the library so synced passkeys work. The tests no longer only test a mock (5.1).
  • MCP. No tool could read a page, so agents wrote blind: get_page_markdown added. Replacing a page would have deleted live blocks, mentions and attachments: blocks are kept from the live document and lossy pages are refused. Comments were re-attached to the first match of a short quote: now only to a unique match. Child-page comments could leak from restricted pages: filtered (6.2, 6.3).
  • To-do board. The ported functions change their argument in place, so the draft's "diff the result" would have written nothing. Deletes versus concurrent edits could lose or strand items. Both specified and tested. Missing features restored: section headings, collapse, move, card rename, delete and resize, undo (2.2, 2.3).
  • Spreadsheet. Two new function names clashed with ported ones; the fill logic would have been rewritten though it was ported with tests. The two largest tasks were split into five. Missing features restored: undo, find and replace, sort, fonts, alignment, indent, clear formatting (3.3 to 3.8).
  • Migration safety. The fallback owner would have become admin of spaces that were never theirs: now a workspace with no matched owner is not migrated. Unconfirmed mindspace sign-ups could have claimed someone's content: ignored. The tool would have queued real notification emails: it now writes through repositories. Verification could pass with empty pages: it now compares content, and any loss fails the run. A crash could duplicate content on re-run: ids are derived and written with their map row. The dry run skipped the steps most likely to fail: it now runs them (7.1 to 7.5).
  • Public links. Mindspace gives every public link an expiry, so the draft would have recreated almost none. This became open question Q6, since answered: see "After the review" below.
  • Tests that could not fail. The central whiteboard merge test passed with a broken rule; it now fixes which write Yjs keeps. The copy path had no behavioural test. Every MCP tool is now run through one permission test (1.3, 1.5, 6.2).
